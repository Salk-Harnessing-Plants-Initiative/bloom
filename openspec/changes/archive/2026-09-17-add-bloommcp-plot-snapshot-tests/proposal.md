## Why

Flagged as a follow-up during review of #675 (bloommcp Dockerfile apt-get trim, #590),
tracked as #713. `bloommcp/tests/tools/test_viz_tools.py` and
`bloommcp/tests/smoke/live_plot_tool_smoke.py` — the only coverage of the 5
`sections/sleap_roots/analysis/` plotting tools (`plot_trait_histograms`,
`plot_trait_boxplots`, `plot_correlation_matrix`, `plot_heritability_bar`,
`plot_variance_decomposition`) — only ever assert `.is_file()` on the generated PNG.
Nothing in CI would catch a rendering regression: a matplotlib/Pillow/numpy dependency
bump, or a refactor that silently changes color mapping, plot geometry, or layout, would
ship with every existing assertion still green, noticed only when someone looks at a
plot.

## What Changes

- **ADD** 5 committed baseline PNGs under `bloommcp/tests/fixtures/plot_baselines/`
  (`{histograms,boxplots,correlation_matrix,heritability,variance_decomposition}_turface_19_baseline.png`
  + a `MANIFEST.json` recording the rendering environment's provenance), generated by a
  new `bloommcp/scripts/gen_plot_snapshots_golden.py` from the exact 5 MCP tool
  entrypoints (not their delegates directly) against the existing `turface_19_final_data.csv`
  fixture — the same fixture and call path `test_viz_tools.py`'s `viz_env` fixture already
  exercises.
- **ADD** `bloommcp/tests/tools/test_viz_snapshot.py`: for each of the 5 tools, render
  against `viz_env` and compare the real output to its baseline via
  `matplotlib.testing.compare.compare_images` (matplotlib's own image-comparison utility —
  **no new dependency**: it needs Pillow, already a hard transitive floor of both
  `matplotlib` and `sleap-roots-analyze`, bloommcp's existing main dependencies) at a
  tolerance (`_TOL = 15`) picked from a real, reproducible measurement — not guessed —
  documented in the test file's module docstring. A companion
  `test_tolerance_catches_a_real_regression` proves `_TOL` isn't a rubber stamp by
  reproducing that measurement live against a deliberately perturbed copy of a real
  baseline.
- **MOVE** the `viz_env` pytest fixture out of `test_viz_tools.py` into a new
  `bloommcp/tests/tools/conftest.py`, so both test files share one definition instead of
  risking silent desync (mirrors `_viz_shared.py`'s own single-sourcing rationale for the
  5 tools it serves). No behavior change to `test_viz_tools.py`'s existing tests.
- **EXTEND** `bloommcp/tests/fixtures/README.md` with a new section documenting
  `plot_baselines/`'s provenance and regeneration instructions, matching the existing
  fixture-documentation convention.
- **ADD** a new `bloommcp-plot-snapshot-testing` capability spec (this is genuinely new
  test infrastructure, not an extension of the existing `bloommcp-smoke-testing`
  capability — these tests are fast/unmarked/fixture-based, unlike that capability's
  `live_smoke`-marked, real-dev-stack-required tests).
- These tests run **unmarked**, in the existing `python-audit` CI job's default per-PR
  sweep — the whole point is that CI catches a rendering regression without a developer
  needing to look at a plot, matching the issue's explicit ask.

## Non-goals

- Not covering the optional plot keys `pca_analysis`/`umap_analysis`/`clustering` can also
  emit (`create_pca_biplot`, `create_pca_scree_plot`, `create_feature_contribution_plot`,
  `create_feature_contribution_heatmap`, `create_umap_colored_by_top_traits`,
  `create_cluster_scatter_pca`, `create_cluster_size_barplot`) — the issue's own diagnosis
  is specifically about `test_viz_tools.py`'s existing `.is_file()`-only gap over the 5
  dedicated plotting tools; these 7 additional optional keys across 3 other tools would
  roughly triple this change's scope for a "lightweight" testing addition (the issue's own
  word, twice). Tracked as **#723** (filed alongside this proposal), not silently dropped.
- Not asserting bit-for-bit cross-platform pixel identity. `_TOL` absorbs legitimate
  FreeType-hinting differences between the Linux baselines and any other OS a developer
  runs the suite on locally; see design.md for the cross-platform risk this accepts and
  the fallback if CI's first real run shows the tolerance needs adjusting.
- Not adding a CI step to upload `compare_images`' `*-failed-diff.png` diagnostic as a
  build artifact on failure — a nice-to-have, but the failure message already names the
  path, and CI doesn't currently upload any other test-produced artifact either.
- Not touching `live_plot_tool_smoke.py` (the live-stack `.is_file()` smoke) — that script
  proves the real bind-mount write path works end-to-end; it is orthogonal to whether the
  *pixel content* is correct, which is this change's entire concern.

## Impact

- **Affected specs**: `bloommcp-plot-snapshot-testing` (new capability, ADDED only).
- **Affected code**:
  - `bloommcp/scripts/gen_plot_snapshots_golden.py` — new.
  - `bloommcp/tests/fixtures/plot_baselines/` — new (5 PNGs + `MANIFEST.json`).
  - `bloommcp/tests/tools/conftest.py` — new (holds the moved `viz_env` fixture).
  - `bloommcp/tests/tools/test_viz_tools.py` — `viz_env` fixture definition removed
    (now sourced from the new conftest); no test behavior changes.
  - `bloommcp/tests/tools/test_viz_snapshot.py` — new.
  - `bloommcp/tests/fixtures/README.md` — one new documented section.
- **Affected CI**: none structurally — the new tests run inside the existing
  `python-audit` job's existing `pytest tests/ -m "not integration and not live_smoke"`
  invocation (no marker added, matching the issue's intent that this run every PR).
- **No new dependency**: `matplotlib.testing.compare` and the `PIL`/Pillow import it needs
  are both already resolvable in the current venv (confirmed locally: `matplotlib==3.10.8`,
  `PIL==12.3.0`, `Pillow` required directly by both `matplotlib>=3.7.0` and
  `sleap-roots-analyze>=0.1.0a5` in `pyproject.toml`'s main `dependencies`).
