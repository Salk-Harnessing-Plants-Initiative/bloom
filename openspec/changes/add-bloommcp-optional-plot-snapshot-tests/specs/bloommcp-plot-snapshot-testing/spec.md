## ADDED Requirements

### Requirement: Baseline Coverage For The Optional Plot Keys

`bloommcp/tests/fixtures/plot_baselines/` SHALL contain one committed baseline PNG for each
of the 8 catalog plot keys the `include_plots=True` path of `pca_analysis` (4),
`umap_analysis` (2), and `clustering` (2) can emit, named
`<catalog_key>_turface_19_baseline.png`. Each SHALL be generated by
`bloommcp/scripts/gen_plot_snapshots_golden.py` against the `turface_19_final_data.csv`
fixture through each tool's real MCP entrypoint at its default parameters — not by calling
the upstream plotter directly — so the committed bytes are the bytes the tool persists.

#### Scenario: Every catalog plot key has a baseline

- **WHEN** a developer inspects `bloommcp/tests/fixtures/plot_baselines/`
- **THEN** it contains `create_pca_scree_plot_turface_19_baseline.png`,
  `create_pca_biplot_turface_19_baseline.png`,
  `create_feature_contribution_plot_turface_19_baseline.png`,
  `create_feature_contribution_heatmap_turface_19_baseline.png`,
  `create_umap_single_trait_turface_19_baseline.png`,
  `create_umap_colored_by_top_traits_turface_19_baseline.png`,
  `create_cluster_scatter_pca_turface_19_baseline.png`, and
  `create_cluster_size_barplot_turface_19_baseline.png`

#### Scenario: The baseline set tracks the tools' catalogs

- **WHEN** a test enumerates `_PCA_CATALOG_KEYS`, `_UMAP_CATALOG_KEYS`, and
  `_CLUSTERING_CATALOG_KEYS` from the tool modules
- **THEN** every key in their union has a corresponding baseline PNG, so adding a catalog
  key without a baseline fails the suite instead of silently shipping uncovered

#### Scenario: Optional-key baselines are regenerable alongside the existing ones

- **WHEN** `uv run --frozen --extra test python scripts/gen_plot_snapshots_golden.py --yes`
  runs
- **THEN** it regenerates the optional-key baselines in the same invocation as the dedicated
  plotting tools' baselines, seeding each tool's `require_clean=True` read via
  `FakeReader.add_cleaned_version` and capturing the committed bytes through the same
  `ResultStore` commit spy, with no live Supabase stack or network access required

### Requirement: Pixel-Diff Coverage For The Optional Plot Keys

`bloommcp/tests/tools/test_viz_snapshot.py` SHALL compare each of the 8 optional plot keys'
real rendered output against its baseline PNG using
`matplotlib.testing.compare.compare_images` at the same `_TOL` constant the dedicated
plotting tools use, and that constant's applicability to these plots SHALL be established by
measurement recorded in `design.md`, not assumed to carry over. Comparisons SHALL address
each figure by filename, never by the tool's `outputs` key ordering, which varies per process.

#### Scenario: A correct render passes for every optional key

- **WHEN** the snapshot test renders `pca_analysis`, `umap_analysis`, and `clustering` with
  `include_plots=True` at default parameters against the `turface_19` fixture
- **THEN** `compare_images(baseline, actual, tol=_TOL)` returns `None` for all 8 keys

#### Scenario: A missing optional-key baseline fails with an actionable message

- **WHEN** a baseline PNG for one of the 8 keys does not exist
- **THEN** the test fails with a message naming the missing path and the
  `scripts/gen_plot_snapshots_golden.py --yes` command that regenerates it, not a bare
  `FileNotFoundError`

#### Scenario: The tolerance is not a rubber stamp for these plots

- **WHEN** the negative-control test uniformly dims one optional-key baseline by 10% via
  `PIL.ImageEnhance.Brightness` and compares it against the unmodified baseline at `_TOL`
- **THEN** `compare_images` returns a non-`None` result — the regression is caught

### Requirement: Measured Detection Limits Are Pinned By Tests

A measured perturbation of an optional plot key that is **not** caught at `_TOL` SHALL be
recorded in `design.md` with its measurement, and SHALL be pinned by a negative-control test
asserting the current (negative) outcome, so any future change to it — in either direction —
fails loudly instead of passing unnoticed. Such a limit SHALL NOT be presented as coverage.

#### Scenario: The clustering scatter's assignment blind spot is pinned

- **WHEN** `clustering` is re-rendered with a different cluster count than the baseline's
  and its `create_cluster_scatter_pca` output is compared against the baseline at `_TOL`
- **THEN** the test asserts `compare_images` returns `None` (not caught), naming in its
  docstring that whole-image RMS dilutes a sparse scatter and that clustering *correctness*
  is covered by `test_clustering_tool.py`'s numeric assertions instead

#### Scenario: The loadings heatmap's single-cell limit is pinned

- **WHEN** exactly one cell-sized region of the
  `create_feature_contribution_heatmap` baseline — sized from the heatmap's real measured
  cell geometry — is recolored and compared against the baseline at `_TOL`
- **THEN** the test asserts `compare_images` returns `None` (not caught), matching the
  structural limit already tracked for `plot_correlation_matrix` as #768
