## ADDED Requirements

### Requirement: Baseline Coverage For The Optional Plot Keys

`bloommcp/tests/fixtures/plot_baselines/` SHALL contain one committed baseline PNG for every
key in the union of `_PCA_CATALOG_KEYS`, `_UMAP_CATALOG_KEYS`, and `_CLUSTERING_CATALOG_KEYS`
**except those a test-visible exclusion set records as producing a platform-dependent canvas**
(6 baselined of 8 keys at time of writing), named `<catalog_key>_turface_19_baseline.png`.
An excluded key SHALL still be rendered and asserted to reach disk, and the exclusion SHALL
be justified by a recorded measurement rather than by preference. Each SHALL be
generated by `bloommcp/scripts/gen_plot_snapshots_golden.py` against the
`turface_19_final_data.csv` fixture through each tool's real MCP entrypoint with
`include_plots=True` and otherwise default parameters — not by calling the upstream plotter
directly — so the committed bytes are the bytes the tool persists.

#### Scenario: Every catalog plot key has a baseline, and no orphans remain

- **WHEN** a test compares the on-disk set
  `plot_baselines/create_*_turface_19_baseline.png` against the union of the three catalog
  key constants imported from the tool modules, less the recorded exclusion set
- **THEN** the two sets are equal — so both a catalog key added without a baseline and a
  baseline left behind after a key is removed fail the suite — and the exclusion set is
  itself asserted to be a subset of the live catalogs, so a stale entry cannot silently
  suppress a key that no longer exists

#### Scenario: Optional-key baselines are regenerable alongside the existing ones

- **WHEN** `uv run --frozen --extra test python scripts/gen_plot_snapshots_golden.py --yes`
  runs
- **THEN** it regenerates the optional-key baselines in the same invocation as the dedicated
  plotting tools' baselines, seeding each tool's `require_clean=True` read via
  `FakeReader.add_cleaned_version` and capturing the committed bytes through the same
  `ResultStore` commit spy, with no live Supabase stack or network access required

#### Scenario: Baseline provenance records what the renders actually depend on

- **WHEN** `MANIFEST.json` is written by the regeneration script
- **THEN** it records the versions of every library these renders depend on — including
  `umap-learn`, `numba`, `llvmlite`, `scikit-learn`, `seaborn`, `adjustText`, `numpy`, and
  matplotlib's bundled FreeType — plus the SHA-256 of the fixture CSV and the resolved seed
  used for each stochastic tool, so a future failure can be attributed rather than guessed at

### Requirement: Pixel-Diff Coverage Extended To The Optional Plot Keys

`bloommcp/tests/tools/test_viz_snapshot.py` SHALL compare each optional plot key's real
rendered output against its baseline PNG using `matplotlib.testing.compare.compare_images` at
the same `_TOL` constant the dedicated plotting tools use, and that constant's applicability
to these plots SHALL be established by measurement recorded in `design.md`, not assumed to
carry over. Comparisons SHALL address each figure by filename, never by the tool's `outputs`
key ordering, which varies per process.

#### Scenario: A correct render passes for every optional key

- **WHEN** the snapshot test renders `pca_analysis`, `umap_analysis`, and `clustering` with
  `include_plots=True` at otherwise default parameters against the `turface_19` fixture
- **THEN** `compare_images(baseline, actual, tol=_TOL)` returns `None` for every baselined
  key

#### Scenario: A missing optional-key baseline fails with an actionable message

- **WHEN** the baseline directory the optional-key comparison resolves against does not
  contain a required baseline
- **THEN** a committed test asserts the failure names the missing path and the
  `scripts/gen_plot_snapshots_golden.py --yes` command that regenerates it, not a bare
  `FileNotFoundError`

#### Scenario: The tolerance catches a real semantic regression, not just a dimming probe

- **WHEN** a negative-control test re-renders a tool with a genuinely different scientific
  parameter — `standardize=False` for `pca_analysis`, a changed cluster count for
  `create_cluster_size_barplot`, or a perturbed loadings value for
  `create_feature_contribution_heatmap` — and compares against the unmodified baseline
- **THEN** `compare_images` reports a difference over `_TOL` in each case

#### Scenario: Both of `_compare_or_fail`'s failure paths are exercised

- **WHEN** a baseline and actual image differ in pixel dimensions (which `compare_images`
  raises as `ImageComparisonFailure`) or a baseline is zero-length or corrupt (`OSError`)
- **THEN** the failure message carries the cross-platform pointer, the same as an ordinary
  RMS-over-tolerance miss, rather than surfacing as a bare traceback

### Requirement: Measured Detection Limits Are Pinned By Tests

A measured perturbation of any baselined plot that is **not** caught at `_TOL` SHALL be
recorded in `design.md` with its measurement, and SHALL be pinned by a negative-control test,
so any future change to it — in either direction — fails loudly instead of passing unnoticed.
Such a limit SHALL NOT be presented as coverage. A negative control SHALL be two-sided: it
SHALL also assert that the perturbation actually changed the image, so that a no-op cannot
satisfy it vacuously.

#### Scenario: The clustering scatter's assignment blind spot is pinned

- **WHEN** `clustering` is re-rendered with a different cluster count than the baseline's
  and its `create_cluster_scatter_pca` output is compared against the baseline
- **THEN** the test asserts the images genuinely differ, that the difference is nonetheless
  under `_TOL` (not caught), and that the RMS remains inside its measured band — naming in
  its docstring that whole-image RMS dilutes a sparse scatter and that clustering
  *correctness* is covered by `test_clustering_tool.py`'s numeric assertions instead

#### Scenario: The cluster-size barplot's same-k membership blind spot is pinned

- **WHEN** `clustering` is re-rendered with `method="hierarchical"`, which yields the same
  cluster count as the baseline but different cluster sizes, and its
  `create_cluster_size_barplot` output is compared against the baseline
- **THEN** the test asserts the difference is under `_TOL` (not caught), so the design's
  claim that the barplot compensates for the scatter's blindness is bounded by a test rather
  than by prose

### Requirement: Baselines Are A Drift Gate, Not A Correctness Oracle

A baseline SHALL be treated as certifying *rendering stability* only, and SHALL NOT be
described as evidence that a figure is scientifically correct: it is generated from the code
as it currently renders, so a figure that is wrong today is frozen wrong. The `plot_baselines/` documentation
and the snapshot module's docstring SHALL state this explicitly, and each baseline SHALL be
visually inspected before it is first committed.

#### Scenario: A new baseline is reviewed before it becomes the reference

- **WHEN** a baseline PNG is generated for the first time
- **THEN** the author confirms the figure is correct — axes and legend labelled, reported
  variance consistent with the numeric golden, clusters and bars present as expected, no
  blank or degenerate panel — and records that check in the PR, rather than committing
  whatever the code happened to emit

#### Scenario: A known upstream figure defect is recorded next to its baseline

- **WHEN** a baselined figure is known to render something scientifically misleading
- **THEN** the limitation is documented alongside the baseline so the next person
  regenerating it knows the reference encodes a defect, instead of reading the committed PNG
  as the intended output
