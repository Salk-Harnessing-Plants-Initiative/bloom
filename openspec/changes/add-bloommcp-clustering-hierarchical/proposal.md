## Why

Tier 5 (#309) shipped the polymorphic `clustering` MCP tool covering k-means and GMM but explicitly
deferred `method="hierarchical"` — `perform_hierarchical_clustering` in `0.1.0a4` returns only a
dendrogram (no `cluster_labels`, no quality scores, no `from_hierarchical_dict`), so the
thin-delegation rule had nothing to wrap. This change is the tracked fast-follow (#422): once
`sleap-roots-analyze 0.1.0a5` ships a public labeled-clustering entry point returning a `ClusterResult`
(labels + sizes + scores) and makes `ClusterResult.random_state` `Optional[int]`, hierarchical drops
in with no contract or schema change.

## What Changes

- **ADD** `"hierarchical"` as a valid `method` value to the `clustering` tool's `Literal` dispatch —
  no retrofit of the contract, schema, or the kmeans/gmm arms; one new `Literal` member and one new
  dispatch arm.
- **BUMP** `sleap-roots-analyze` pin to `>=0.1.0a5` in `bloommcp/pyproject.toml` (and `uv.lock`) to
  pull in the public hierarchical entry point. This is the **hard dependency** — the MCP must not
  orchestrate the tree-cut / optimal-k / quality-metric composition itself (thin-delegation rule).
- **SEED HANDLING**: hierarchical is deterministic — no `random_state` parameter — so the tool records
  `seed = None` in `Provenance`, mirroring `qc_clean` / `pca_analysis`. The existing contract `seed=None`
  path (designed in #309 for this case) is consumed without modification.
- **RETURN** the upstream `ClusterResult` (hierarchical variant) inline + persist the versioned run +
  resource links, exactly mirroring the kmeans/gmm pattern (labels CSV with sample identity,
  `cluster_result.json`, manifest with `based_on_version` and `input_sha256`).
- **REJECT** hierarchical-incompatible controls: `n_clusters`, `max_clusters`, `n_components`,
  `max_components`, and `covariance_type` are kmeans/gmm-only — passing them with
  `method="hierarchical"` returns a `BloomMCPError` with code `invalid_input`, consistent with the
  cross-method guard already in place for kmeans vs gmm.
- **DETERMINISM ORACLE**: hierarchical is deterministic — same input → identical `cluster_labels`
  (no seed tolerance needed, no `random_state` forwarded).
- Tests cover: `tools/list` presence, schema round-trip, provenance records `seed = None`, the
  determinism oracle, `require_clean` consumption + certified-set restriction (reuse existing
  `_validate_trait_subset` helper), structured error envelope, and a characterization snapshot
  through the tool at the recorded golden parameters.
- Extend `make bloommcp-smoke` with a hierarchical leg alongside the existing kmeans/gmm legs.
