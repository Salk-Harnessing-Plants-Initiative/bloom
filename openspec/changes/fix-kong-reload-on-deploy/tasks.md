## 9. PR review round 1 (PR #635) — fixes applied

A 5-agent adversarial review of the actual PR diff (not just the proposal, which had already been through 3 rounds) found one real BLOCKING gap and several IMPORTANT items:

- **BLOCKING, fixed**: `Rollback on failure`'s `git reset --hard` + `up -d` cannot detect that `kong.yml`'s content reverted, for the identical reason the forward-path bug existed — if a later step failed after `Restart Kong config` already succeeded, rollback would leave Kong on the failed deploy's config indefinitely. Fixed by adding the same restart-and-health-poll logic to both rollback steps, gated on the same `kongfile_changed` output, positioned after each rollback's own `up -d --wait`. See `design.md` Decision 7 and the new "Rollback MUST restore a config-delivering service's content too" requirement in `spec.md`.
- **IMPORTANT, fixed**: `before_restart_count`'s missing-marker fallback defaulted to `0`, which could inflate the crash-loop check's delta and falsely stop a healthy Kong on a transient glitch. Now passes through with no default, so the script's own argument validation rejects it with a clear usage error instead.
- **IMPORTANT, fixed**: `docker compose restart kong --timeout 10`'s `--timeout` only bounds Docker's internal graceful-stop period, not the whole command's wall time if the daemon itself hangs. Both forward-path and rollback-path restarts are now wrapped in an external `timeout 60`.
- **IMPORTANT, fixed**: the crash-loop check's secret extraction lacked the `:?` guards the pre-existing smoke-test step uses for the same pattern (currently safe in practice since `validate_env.sh` already guarantees non-empty values, but inconsistent). Added for defense-in-depth.
- **IMPORTANT, fixed**: `check_kong_restart_delta.sh`'s `after=$(docker inspect ...)` had no explicit failure handling for the narrow race where the container disappears between resolving its id and inspecting it — under `set -e` it would abort with a raw bash error instead of the script's own clear `::error::` message. Now wrapped with an explicit error path.
- **IMPORTANT, fixed**: the docker-stub in `test_check_kong_restart_delta_script.py` didn't validate `docker inspect`'s arguments, so a regression that inspected the wrong container or dropped `--format` would still pass every test. Tightened to validate both.
- **IMPORTANT, fixed**: `design.md`'s "brief... typically a few seconds" framing undersold the real worst-case Kong-unavailability window (up to the full 120s health-poll bound), during which real end-user requests through Caddy would see 502s. Reworded to state the honest worst case and note there's no maintenance-window mechanism in this pipeline today (a pre-existing, not newly-introduced, gap).
- **IMPORTANT, addressed via correction, not a code change**: the "separate commits" TDD claim (see note above).
- Removed a vestigial test (`TestCheckKongRestartDeltaScriptShapeReady`) whose docstring described a RED-phase guard purpose it no longer served post-implementation, and whose one real assertion was already redundant with `test_crash_loop_check_invokes_script_with_threshold_2`.

## 10. PR review round 2 (PR #635) — fixes applied

Round 1's fixes were verified correct in a second review pass, which also did a fresh adversarial pass specifically on the round-1 rollback fix (new, previously-unreviewed code) and found one more real issue:

- **IMPORTANT, fixed**: the rollback's Kong-restart command (`timeout 60 docker compose ... restart kong --timeout 10`) was itself unguarded inside the rollback step's `set -e` SSH block. By the time this line runs, the critical work (`git reset --hard` and `up -d --wait`) has already succeeded — a Kong-restart hiccup here is a secondary, best-effort concern, but an unguarded failure would abort the whole script and make GitHub Actions report the rollback step as FAILED, misleading on-call into thinking the code/env revert failed when it actually succeeded. ## 11. PR review round 3 (PR #635) — fixes applied
