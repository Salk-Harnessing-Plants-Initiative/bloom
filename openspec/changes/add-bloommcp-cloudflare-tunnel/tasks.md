  - **Test first:** `tests/unit/test_pr_checks_env_ci_tunnel_hostname.py` — statically greps `pr-checks.yml`'s `.env.ci`-generation step for a `TUNNEL_HOSTNAME=` placeholder line, and asserts there is **no** corresponding `CLOUDFLARE_TUNNEL_TOKEN=` line added there (guards against reintroducing the unnecessary one).   - **Test first:** `tests/unit/test_deploy_staging_activates_tunnel_profile.py` — asserts BOTH staging `docker compose up` invocations include the profile flag/env var, and that neither of the two production invocations does. Fails before 1.4.

This exercises `trusted_proxies` gating by *peer address* — a distinct code path from 3.4.
- [ ] 3.4 `tests/integration/test_caddy_tunnel_waf_rejects_missing_header.py` — from the trusted `supanet` peer, send a request with **no** `Cf-Connecting-IP` header at all (not spoofed, simply absent); confirm it's still rejected, because the client-IP fallback resolves to the peer's own (non-Anthropic) address. This exercises the `client_ip_headers` fallback behavior specifically — kept as a separate test from 3.3 so a bug in one path can't be masked by the other happening to also reject for an unrelated reason.
